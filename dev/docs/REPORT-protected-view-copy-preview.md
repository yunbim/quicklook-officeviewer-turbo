# Protected View「副本预览」改造 — 实现与验证

日期：2026-09-12 ｜ 范围：`QuickLook.Plugin.OfficeViewer` 插件（已编译并部署到本机安装目录）

---

## 1. 需求 → 实现

| 需求 | 实现 |
|---|---|
| 只预览、**不动原文件** | 命中 `Zone.Identifier` 时，**流式复制**一份到 `%TEMP%\QuickLook\OfficeViewer\`，**只对副本**摘标识，预览副本。原文件只被只读打开，字节不变 |
| 预览页里显示"这是副本"提醒 | 预览区上方加一条琥珀色提示条（独立布局行，非浮层） |
| 给按钮让用户**手动**决定是否解除源文件保护 | 提示条右侧按钮「解除源文件保护视图」→ 只对**原文件**摘标识，成功后提示条变绿并显示「✓ 已解除」 |
| 不影响普通文件的首次预览体验 | 未带标识的文件走**完全原有路径**：无提示条、无复制、无额外 I/O |

顺带删掉了原来的确认弹窗（`Be careful - files from the Internet…`），**弹窗不再存在**。

## 2. 改动的文件

新增：

- `ProtectedViewPreview.cs` — 副本的生成 / 摘标识 / 清理。
  流式复制（read→write 到全新文件）本身就**不会**继承备用数据流，摘标识只是复核；复核用 `IsZoneBlocked`，摘除用 `RemoveZone` + `DeleteFileW(path+":Zone.Identifier")` 兜底。
  副本名 = `原名-<路径+大小+mtime 的哈希>.ext` → 文档改过就换新名，不会命中旧副本；被热宿主占用时退回随机后缀。
- `ProtectedViewBanner.cs` — 提示条 UI（自绘颜色，不受深浅主题影响）。

修改：

- `Plugin.cs` — `View()` 判断标识 → 决定预览原文件还是副本；`Init()` 清理 1 天前的旧副本；`Cleanup()` 尽力删除当前副本。删除全部 `MessageBox` 逻辑与 `AlwaysUnblockProtectedView` 设置的使用。
- 安装目录 `UserData\QuickLook.Plugin.OfficeViewer.config` — 移除已失效的 `AlwaysUnblockProtectedView` 键。

## 3. 验证（`tools/verify_protected_copy.py`，全部 PASS）

每个场景都从冷启动 QuickLook 开始，并读取真实像素判定：

| 场景 | 期望 | 实测 |
|---|---|---|
| **T1** 普通文件（无标识） | 无提示条、无临时副本、正常渲染 | 提示条琥珀色像素 0、临时副本 0、渲染正常 → **PASS** |
| **T2** 带 `Zone.Identifier` | 无弹窗 + 正常渲染 + 提示条 + **原文件仍带标识** | 无弹窗、渲染正常、提示条 152 692 px、副本已生成、**原文件标识仍在** → **PASS** |
| **T3** 真实鼠标点击按钮 | 原文件标识被摘除 + 提示条变化 | 点击 (2119,107) → 源文件标识**消失**、提示条变绿 127 312 px → **PASS** |

> T2 的「原文件仍带标识」是本次改造的核心断言——只测"能预览"是测不出"有没有动原文件"的。
> T3 用的是**真实鼠标事件**（从截图像素定位按钮 → 换算屏幕坐标 → `SetCursorPos` + `mouse_event`），不是直接调用内部函数。

截图：`shots/copy-t1-plain.png`（无提示条）、`shots/copy-t2-marked.png`（副本提示条 + 按钮）、`shots/copy-t3-after-click.png`（点击后变绿）。

## 4. 运维

- **副本位置**：`%TEMP%\QuickLook\OfficeViewer\`；预览关闭时尽力删除，删不掉（被热 Office 进程占用）的由插件加载时清理，**保留 1 天**。
- **回滚**：安装目录里有两级备份 ——
  - `…OfficeViewer.dll.opt-prev` = 本次改造**之前**的优化版（只回滚这一步）；
  - `…OfficeViewer.dll.stock-4.5.0` = 上游原版（回滚全部优化，含速度优化）。
  两者都是改名即可生效的 DLL，替换前请先退出 QuickLook。
- **改了代码怎么重新生效**：`dotnet build` → 覆盖安装目录 DLL → 重启 QuickLook（`SettingHelper` 会缓存配置 XML）。

## 5. 顺带解决的两件事

1. **"找不到 QuickLook 图标"**：查明系统里**从来没有**任何 QuickLook 快捷方式（桌面 / 开始菜单 / 启动项全空），而且当时 QuickLook 并未运行 —— 托盘图标只有运行中才有，且 Win11 默认把它收进溢出区（时钟旁的 `^`）。
   已生成桌面 + 开始菜单 `QuickLook.lnk`，并用 Shell 回读校验目标 / 工作目录 / 图标全部正确（工具：`tools/shortcut-maker/`）。
2. **一个影响了此前判断的取证缺陷**：本机显示缩放是 **200%**，而我的截图脚本不是 DPI 感知进程，Windows 因此**虚拟化坐标** —— `GetWindowRect` 只报了一半尺寸，`PrintWindow` **只截到窗口左上角四分之一**。
   之前"提示条文字被裁切 / 按钮不见了"，以及更早"Word 内容溢出、像 web 视图"的判断，都是这个缺陷造成的**假象**。已修复（取证进程启动即声明 per-monitor DPI 感知）。
   用全窗口截图重新观察：**Word 预览是正常的分页纸张视图**，并没有溢出。若你屏幕上仍觉得视图不对，告诉我，我再单独查（按你之前的要求，这一步我没有擅自展开）。

## 6. 已知取舍

- 提示条会让**受保护文件**的可视预览区**矮约 43 px**（普通文件不受影响）。这是为满足"必须在页面里给出提醒 + 按钮"付出的代价——`WindowsFormsHost` 会把重叠的 WPF 元素盖住，提示条只能占独立布局行，无法做成悬浮层。
- 副本是**文件的完整拷贝**：受保护的大文件（如上百 MB 的 PPT）会多一次磁盘复制，约几十毫秒量级；普通文件不涉及。
- 按钮解除标识是**永久改动**（等同于文件属性里的"解除锁定"），所以设计成必须由你手动点击——这也是这次改造的初衷。
